## 4. PR-014 实现（saga 验收面）

`src/lva/providers/hub_runtime.py` 补齐两项：

### 4.1 profile required

`switch_model` 的 load 失败分支现在区分**缺 profile** 与一般失败：缺 profile → `PROFILE_REQUIRED`，其余 → `MODEL_LOAD_FAILED`。理由（计划 L593）：**LVA 不得猜 `-ngl`/`-c`/`mmproj`**。

### 4.2 rollback —— 这里我第一版做错了，且是**被既有测试纠正的**

**我的第一版**：失败时把 binding 恢复到 previous 并把状态置为 `degraded`/`unbound`。

**既有测试 `tests/fault/test_fault_matrix.py::test_fault_hub_load_failure_missing_profile` 立刻失败**（它断言 `status == "failed"`）。我据此回查计划，找到 **L636**：

> 任一步失败：binding 进入 `FAILED/DEGRADED`，旧 turn 不可复活；若旧 model 仍健康，可通过**显式 rollback operation** 重新 bind，**不能靠恢复旧内存状态假装成功**。

**所以错的是我，不是测试。** 已改为：`rollback()` 记录 `previous_binding`（供显式 rollback 操作使用）并回填 `active_model_id`/`load_origin`，但**不调用 `_update_status`**——状态保持失败路径设置的 `FAILED`。把状态翻回 `ready` 正是 L636 禁止的「假装成功」。

**这是本项目第一次由既有测试直接纠正我的语义错误**，值得记录：`tests/fault` 的 7 项不是摆设。
